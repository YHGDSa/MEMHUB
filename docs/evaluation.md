# 验证与指标

## 1. 已做的验证（行为级，2026-10-28 一次完整演练）

方法：手动断开隧道 → 离线写入 → 恢复 → 补推 → 再拉取 → 删除 → 检查快照。
产出：下表逐行核对；后来把同样的路径固化进 `test/smoke.mjs`（stub 上游可切换在线/离线），现在用一条命令复现其中大部分断言。

| 场景 | 预期 | 实测 |
|---|---|---|
| 隧道断开后写入（中文） | 写入成功、可搜、中文完整 | 200；`upstream:"offline"`、`pendingWrites:1`；中文无乱码 |
| 隧道恢复后同步 | 该条出现在上游、本地清零 | 上游内容一致；`pendingWrites:0` |
| 写入 → 推送 → 再拉取 | 不产生第二份 | `added:0`，两侧条数不变 |
| 写入后删除 | 两侧同时消失 | 本地删 + 上游删，无残留 |
| `scope:"private"` 写入 | 不进入上游 | `pendingWrites` 保持 0，上游条数不变，本地可搜 |
| 含凭据写入 | 落库即脱敏 | `redacted:3`，正文已是 `[REDACTED]` |
| 技能只在目录里 | 不会被 HTTP 写入 | `POST /hub/skills` → 409；reindex 后可检索 |
| 备份脚本 | 生成可导入的完整快照 | `backups/hub-<ts>.json`，含全部记忆与技能 |
| 中文走内联 curl | 会写坏数据（反例） | 变本地代码页/`U+FFFD`，样本已删；改为文件体 |
| 推送字段透传 | 标签作为 `concepts` 一并发送 | 修复前上游 `concepts` 恒空，修复后一致 |

## 2. 自动化覆盖

| 套件 | 断言数 | 覆盖 |
|---|---|---|
| `test/smoke.mjs` | 41 | 鉴权、离线写、离线搜、作用域隔离、脱敏（3 处命中）、恢复补推、去重、在线删除、离线排队即删、导入导出、技能索引与只读、快照一致性、墓碑（拦截重写 + 计数） |
| `test/multi-hub.mjs` | 19 | 两机一上游：单向/双向复制、同事实重复收敛、修订传播与旧版本压缩、删除传播、复活拦截、上游丢行后的自我修复 |

两个套件都在 CI 里跑（`.github/workflows/ci.yml`）。

**不覆盖**：并发写同一条记忆（LWW 会丢一侧）、真实隧道断开（用 stub 上游模拟）、WAL checkpoint 行为、超大正文、跨平台路径、墓碑 TTL 到期后的重新记录。这些是明知的空白，不假装覆盖。

## 3. 指标（尚未测量，写清楚口径再测）

| 指标 | 口径 | 怎么测 | 现状 |
|---|---|---|---|
| 写入可用性 | 上游不可达时写入成功率 | stub 侧强制 503，连续写 N 条，统计 200 占比 | 未测（smoke 只验证单条语义） |
| 补推完成时间 | 上游恢复 → `pendingWrites:0` | 记录恢复时刻与轮询收敛时刻 | 未测（设计值 = 一个轮询周期 ≤60 s） |
| 去重正确性 | 重复行数 | 写入→推送→拉取循环 k 次后的行数差 | 已验证 1 轮，未做 k 轮 |
| 检索有效性 | 10 条 query 的 top1/top3 命中 | 人工标注期望命中，统计命中率 | 未测 |
| 端到端延迟 | 单条 remember/搜索 P95 | 本机压测 1000 次 | 未测 |

> 规则：没有测量就不写“提升 X%”。上面五行为空是诚实的空白，不是被省略的成果。
