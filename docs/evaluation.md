# 验证与指标

## 1. 已做的验证（行为级，2026-10-28 一次完整演练）

方法：手动断开隧道 → 离线写入 → 恢复 → 补推 → 再拉取 → 删除 → 检查快照。
产出：下表逐行核对；后来把同样的路径固化进 `test/smoke.mjs`（stub 上游可切换在线/离线），现在用一条命令复现其中大部分断言。

| 场景 | 预期 | 实测 |
|---|---|---|
| 隧道断开后写入（中文） | 写入成功、可搜、中文完整 | 200；`upstream:"offline"`、`pendingWrites:1`；中文无乱码 |
| 隧道恢复后同步 | 该条出现在上游、本地清零 | 上游内容一致；`pendingWrites:0` |
| 写入 → 推送 → 再拉取 | 不产生第二份 | `added:0`，两侧条数不变 |
| 写入后删除 | 两侧同时消失 | 本地删 + 上游删，无残留 |
| `scope:"private"` 写入 | 不进入上游 | `pendingWrites` 保持 0，上游条数不变，本地可搜 |
| 含凭据写入 | 落库即脱敏 | `redacted:3`，正文已是 `[REDACTED]` |
| 技能只在目录里 | 不会被 HTTP 写入 | `POST /hub/skills` → 409；reindex 后可检索 |
| 备份脚本 | 生成可导入的完整快照 | `backups/hub-<ts>.json`，含全部记忆与技能 |
| 中文走内联 curl | 会写坏数据（反例） | 变本地代码页/`U+FFFD`，样本已删；改为文件体 |
| 推送字段透传 | 标签作为 `concepts` 一并发送 | 修复前上游 `concepts` 恒空，修复后一致 |

## 3. 实测结果（2026-11-22，`node test/metrics.mjs`）

口径：Windows 本机、单进程、随机端口、stub 上游（可切换在线/离线）；不经真实隧道、不含真实网络与并发。复跑命令：`node test/metrics.mjs`（可用 `METRICS_WRITES` / `METRICS_SEED` 调整规模）。

| 指标 | 口径 | 实测 |
|---|---|---|
| 写入可用性 | 上游离线，连续 200 次 `remember` | **200/200 = 100%** |
| 写入延迟（离线） | 同上，端到端 P50 / P95 | **2.8 ms / 4.0 ms** |
| 补推收敛 | 上游恢复后显式 sync 直到 `pendingWrites:0` | 5 轮 **494 / 50 / 54 / 55 / 69 ms**（积压 200 / 20 / 20 / 20 / 20 条；2 / 1 / 1 / 1 / 1 次 sync） |
| 去重稳定性 | 连续 5 次 sync 的 `pull.added` | **0 / 0 / 0 / 0 / 0**，行数 280 → 280 |
| 检索延迟（1000 行） | `smart-search` 端到端 P50 / P95 | **6.5 ms / 8.1 ms** |
| 快照一致性 | `livez.memories` 与 `snapshot.count` | 1280 == 1280 |

读数说明（避免把数字当成它不代表的结论）：

- **补推收敛的 50—70 ms 是「显式 sync」的路径**，不是 60 s 轮询的真实延迟；定时器路径的设计上限仍是一个周期（≤60 s）。首轮 494 ms 是 200 条积压、每轮 `pushOutbox` 最多推 100 条（2 次 sync）的结果。
- **写入延迟是空队列、单条串行**的数字；并发写入没有测（SQLite 单写者本来就串行）。
- **检索 1000 行 P95 8 ms** 只说明 LIKE 打分在这个规模可用，不说明语义召回质量——命中率仍然未测。
- 快照刷新时机：同步成功后、每 5 分钟定时器、删除后，以及**批量导入后**（本次测量发现 import 原先不刷新快照，已修）。

## 4. 仍未测（说清为什么不写数字）

| 指标 | 为什么还没测 | 要测需要什么 |
|---|---|---|
| 检索有效性（top1/top3 命中） | 需要人工标注金标 query，10 条也要人判 | 10 条 query + 人工标注，约半天 |
| 真实隧道断开的收敛 | stub 只模拟 HTTP 503，不模拟 SSH 断开与重连 | 一台可达的上游 + 30 s 断网脚本 |
| 并发写入 | 单写者假设下没有并发路径可测 | 换 Postgres 或改多进程模型 |
| 超大正文（>2 MB） | 请求体上限 2e6 已在代码里，但没测边界行为 | 边界用例 + 分片策略 |

> 规则：没有测量就不写“提升 X%”。上面四行是诚实的空白，不是被省略的成果。

## 5. 如果要继续做

1. 用 10 条 query 的命中率给检索一个可信基线，再决定是否换 FTS5（ADR-008 的触发条件之一）。
2. 把 stub 上游换成真实隧道，补一条“真实断开 30 s”的集成测试。
3. 用 `node --test` 包一层，让断言可以按文件拆分（当前是单脚本顺序执行）。
4. 把 `metrics.mjs` 的输出存成 `docs/bench-<date>.json`，好比较改动前后的回归。
