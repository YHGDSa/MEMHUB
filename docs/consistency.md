# 多机一致性：在四个端点的约束下做去重、版本与墓碑

> 背景：实验证明“两台机器各自跑 hub、共享一个上游”时，增量同步只能保证**追加复制**；同一事实被两台机器各记一遍会变成两份，修订只能追加新记录，删除也不会传播。这里记录标准解为什么可以只依赖上游已有的四个端点。

## 1. 问题与约束

**现象（`docs/topologies.md` §4 的实测）**

1. 重复：A、B 独立记录同一事实 → 上游两份，双方各持一份。
2. 更新不传播：没有更新通道，只能追加新记录；旧记录永久留在上游。
3. 删除不传播：A 删了，B 的副本还在；B 一旦重写，内容会“复活”。

**约束**：上游是别人（可能是官方服务），只能承诺 `livez / export / remember / forget` 四个端点，不能要求它提供 `merge`、`update`、`tombstone` 或版本号。

## 2. 决策：把元数据放进 tags

上游虽然不能加字段，但**能存标签**（官方实现还会把 tags 映射成 concepts）。于是：

| 元数据 | 形式 | 用途 |
|---|---|---|
| 内容 id | `cid:<sha256(normalized project\|type\|title\|content)[:16]>` | 跨机器识别“这是同一条事实” |
| 实体 id | `eid:<id>` | 同一条记忆的多个版本共享，用于 LWW |
| 墓碑 | `tomb:<cid>` + `type: tombstone` | 跨机器传播删除 |

写入时由本地计算，随 remember 上行；拉取时从 tags 还原。**上游零改造**，只需要它别丢标签——这一点在 `docs/evaluation.md` 的字段透传演练里已经验证过。

## 3. 三条链路的改动

### 3.1 写入：算 id，查墓碑

```
redact → cid = hash(normalized 记录) → eid = 新随机或继承
      → 若是活跃墓碑 → 409（同一内容在 TTL 内不允许重新落库）
      → tags += cid:/eid:
      → 落库 + outbox
```

### 3.2 拉取：按 cid 去重，按 eid LWW

对每条上游记录依次判断：墓碑 → 记录墓碑并删除本地同内容行；自己推过的 → 跳过；同 cid 已存在 → 只保留一行；同 eid 已存在 → `updated_at` 新的覆盖旧的内容；都不是 → 作为新记录插入。

### 3.3 删除：写墓碑而不是只删

```
本地记墓碑（cid → deleted_at）
→ 取消该记录的待推送
→ 转发上游 forget（删掉已上浮的那份）
→ 入队一条墓碑记录（remember，type=tombstone，tags=tomb:<cid>）
```

其它机器下次同步看到墓碑，就删掉自己的副本；在 TTL 内重新写同一内容会被拒绝（409），这是“删除不复活”的关键。TTL 过后允许重新记录——墓碑不是永久封禁。

### 3.4 修订：同 eid 的新版本

`POST /agentmemory/revise` 更新本地行（新 cid、`updated_at` 刷新、`version+1`），并以同 `eid` 追加一条上游记录。其它机器拉取时按 eid 命中旧版本 → LWW 覆盖，不会多出一条平行事实。

## 4. 全量对账（`POST /hub/reconcile`）

增量同步永远不会主动删数据，所以还需要一个“拿全集比一次”的动作：

| 步骤 | 解决的问题 |
|---|---|
| 先 pull | 让本地与上游对齐到同一时刻的快照 |
| 按 cid 分组，重复组保留最新、`forget` 其余 | 两台机器各记一遍产生的重复 |
| 按 eid 分组，旧版本 `forget` | 修订留下的一串历史记录 |
| 本地按 cid 去重 | 本地自己产生的重复（例如导入） |
| 本地已推但上游缺失的行重新入队 | 上游被清理/丢数据后的 self-heal |
| 过期墓碑：删本地标记 + `forget` 上游墓碑记录 | 防止 export 无限增长 |

返回一份可读报告（`dupsRemoved / versionsRemoved / repushed / tombstonesCompacted / cleaned`），便于在面试或运维时解释“这次修了什么”。

## 5. 代价与不做的部分

- **没有向量/语义级去重**：只有归一化后完全一致的内容才会被识别为重复；换个说法写就是两条。
- **没有实体级墓碑**：墓碑按内容标记；删掉一个版本不会连带删除同实体的其它历史版本（对账会收敛版本，但语义上不是“删实体”）。
- **单写者不跨机**：每台机器内部仍是单写者；跨机靠“追加 + LWW + 对账”，不是分布式共识。
- **墓碑有 TTL**：默认 30 天（`tombstoneTtlDays`），过后同一内容可以被重新记录。要永久封禁需要持久黑名单，不在本实现范围。
- **对账是 O(全量)**：条数大了要分页拉 export；当前实现一次性拉全集，适合几千条以内。
